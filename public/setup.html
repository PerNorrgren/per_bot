First-run setup
Let's set this up
This runs once, for this deployment only. Nothing here is shared with any other facilitator's copy of this app — each one is fully independent.
Identity
The short name shown in places the browser controls directly, not your own pages — dialog boxes, the browser tab, and a bookmark/home-screen icon label. Falls back to the organisation name above if left blank.
A square image works best — this becomes the browser tab icon, bookmark icon, and home-screen icon everywhere the app is added or bookmarked. Uploads immediately; there's nothing else to save for this one.
Legal & contact
This appears in your Privacy Policy, Terms of Service, and other legal documents — get it exactly right, since these are real compliance documents.
Used as the sender identity for system emails, and shown in your legal documents as the contact address.
Payments
Accept payments through this app
If you don't want to charge for membership or courses at all, switch this off — every pricing and checkout screen disappears, and you manage access manually from the admin panel instead.
If you keep this on, you'll still need to add your own Stripe keys as environment variables in Railway (STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET) — those are secrets and can't be entered here. Payments will simply show "not yet available" until you do.
Talk & landing experience
A quiet first screen — today's message, a 2-minute-calm option, a few practices for a busy mind — instead of dropping straight into a live conversation. Turn this off to instantly revert to the original direct-into-Talk landing, no redeploy needed.
Shown in place of "Talk" wherever a client picks who they're with — e.g. their own facilitator's name, alongside yours.
Off means everyone hears the default voice — which is also the only voice that gets cached for instant, free replays of the short signal-practice scripts (see the Signal Scripts admin panel). Anyone who's already picked a different voice keeps it; this only stops new choices while it's off.
Skins
A lighter-weight brand layer for a specific group within this same deployment — e.g. a university cohort with their own login page, logo, and colour, while everything else (accounts, content, features) stays exactly the same app. Someone who registers through a skin's login link keeps that look everywhere in the app from then on. This is branding only — it doesn't change which content or courses anyone can see.
Edit skin

Applied on the skin's own login/register pages. Doesn't yet re-colour the rest of the app after login — that's a bigger piece, left for if it's ever actually needed.
Legal documents
Terms, Privacy Policy, and similar published documents. Scope one to a skin if it needs to differ — e.g. a different jurisdiction's terms for a skin serving a different market — otherwise it applies everywhere.
New document
Used in the URL: /legal/[slug]. Leave blank to auto-generate from title. To create a new version of an existing document, use the same slug (and same skin) as the existing one.
